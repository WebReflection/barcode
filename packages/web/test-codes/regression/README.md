# Committed regression fixtures

Unlike `test-codes/field/` (personal, gitignored), these are small,
non-sensitive specimens that a shipped bug was reproduced on. The e2e
suite scans them directly with `scan({ image })`; every fixture must
either decode to its recorded value or be a documented hard negative
(used to bound latency).

| file | expected | context |
| --- | --- | --- |
| `code32-aic-2026-11-19.jpeg` | `code32` / `A938261563` | iPhone screenshot of the docs scanner on an Italian medicine box. The printed `A938261563` is Code 32 (Italian Pharmacode): the raw Code 39 carrier is `VYTH1V`. The wide band was missed by the compact-cluster ROI; the local threshold also merged the thin spaces. Covers both the linear ROI and the Otsu ROI fallback. |
| `gs1-datamatrix-box-2026-11-19.jpeg` | `datamatrix` / `901050883\x1d100006316163\x1d` (and `ean13` / `4006387122584`) | iPhone photo of a product box, shot 90° rotated, holding **both** an EAN-13 and a GS1 DataMatrix. Pinned four fixes: FNC1 in the first codeword is a mode flag (a GS1 DM used to decode to `None`); a crease cut the finder L into 6–29px pieces of an 88px leg (no corner formed); the low-contrast label only binarizes at the 0.7 threshold; and a still's linear fast-path used to hide every 2D tier (the scan returned EAN-13 and never asked the DataMatrix). The DataMatrix is more centered than the EAN-13, so the default "everything" scan resolves the DataMatrix. On a GPU phone the fixed-0.5 GPU floor force-inks this glossy label into noise; the still DataMatrix tier therefore re-reads it on a CPU mask (`STILL_CPU_FAMILIES` in `api/worker.js`), which takes the box from a >5s miss to ~0.6s. |
| `qr-hard-negative-2026-11-19.jpeg` | no read (hard negative) | The same box, a small QR on a crumpled/glossy surface that neither zxing nor this SDK reads at any rotation/upscale. It used to burn 23s in "everything" mode because the still latency was advisory. The deadline test pins the whole still scan to `latency` + a small fixed overshoot. No content assertion: a future decoder that reads it should flip this row to an expected value. |
| `pharma-real-code-2026-11-20.jpeg` | `itf` / `0122508903` **with default formats** | iPhone photo of a Dompé pharma box: the bottom ITF-10 is tiny in the whole 1152×2048 frame and the DataMatrix above it is covered by a sheet of paper. This is the regression the field found: the barcode carries `0122508903` (the printed `012250890` omits the mandatory ITF-10 check digit `3`), but the decoder missed it and a Code 128 false positive (`0BJVcB`) confirmed instead. Root cause: the ITF stop required its wide bar to be the row's **last ink** — the label border/seal shares the row, so every frame was rejected. The stop is now identified by the quiet zone after it. The e2e check runs the default "everything" scan, so it also pins that the true ITF outranks the same-bars Code 128 false positive. |
| `pharma-itf-close-2026-11-20.jpeg` | `itf` / `0122508903` | Closer view of the same bottom barcode on the Android camera (1080×1080). The printed label border is still on the rows to the right, which is exactly the stop-rule regression; keeps a native-pitch close-up beside the whole-picture iPhone photo. |
| `pharma-box-2026-11-20.jpeg` | `code32` / `A042005013` (default "everything") | Regular-zoom view of the same box, holding three codes: Code 32 top/bottom (`A042005013`), DataMatrix (`0122508903181WJP`) and the ITF-10 (`0122508903`). The default scan returns the most centered one (Code 32); the filtered scans each read their own. Keeps the multi-code coexistence check on a second real label. |
| `code39-blur-tilt-mask-2026-11-22.png` | `code39` / `ABC-1234` | **Synthetic** hardening fixture: the binarized mask of a 3 px/module Code 39 at 6° roll with gaussian blur 1.2. zxing reads this exact mask; the upright row scanner did not. Pins the still-only small-roll source retry (`api/worker.js`): the source is rotated by ±3/±4/±8°, re-binarized and read again only after every straight pass missed. |
| `databar-blur-tilt-mask-2026-11-22.png` | `databar` / `(01)40063813339314` | **Synthetic** hardening fixture: the GPU binarizer's 0.75 mask of a 2 px/module GS1 DataBar Omni at 6° roll with gaussian blur 1.2. zxing reads this exact mask; the SDK misses it on every straight still pass (linear ladder, full sweep, Otsu ROI) and reads it only after a **−3°** source rotation. The ±3 pair was added for this case: a 6° roll leaves a 2–3° residual that the DataBar row scanner tolerates (Code 39 needs ±4 instead). The committed file is the **mask**, so the gate runs on the CI's CPU-only Chromium. |
| `ean13-blur-tilt-mask-2026-11-22.png` | `ean13` / `4006381333931` | **Synthetic** hardening fixture (no personal content): the binarized mask of a 2 px/module EAN-13 at 6° roll with gaussian blur 1.2. The decoder's whole-row 95-module quantizer rejected every row (blur widens some runs and merges others) while zxing reads the same grayscale scene. Pins the per-digit variance fallback (`try_variance` in `barcode-ean13`), which matches each 4-run digit locally and still rejects a bad check digit. The committed file is the **mask** so the gate is binarizer-independent (CI has CPU-only Chromium); re-binarizing a crisp mask reproduces it. |
